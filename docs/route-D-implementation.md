## 1. 目标与边界

### 1.1 一句话目标

在一台 RK3588 上，把一张平面的 2D 人像变成**有真实纵深的立体影像**——观众左右移动头部时，画面里的人物与背景产生反向视差，看起来像"隔着一层玻璃在看一个人"，并带有呼吸、眨眼等微动，产生"在场"的错觉。

### 1.2 三条设计原则

1. **不做全 3D 重建**。不追求多边形数量，追求"看不出是假的"。
2. **主动规避恐怖谷**。半透明、辉光、降饱和是设计语言，不是事后补丁。
3. **全部本地化**。影像与声音不出设备，不上云。

### 1.3 明确不做（Non-Goals）

| 不做 | 原因 |
|---|---|
| 全身骨骼动画 | 已确定不使用陀螺仪，2.5D 方案不承载全身运动 |
| 实时 3DGS / NeRF 重建 | RK3588 无 CUDA，训练不可能；渲染方案另立路线 B |
| 语音对话 / 人格模拟 | 属演示层，本方案只负责"影像呈现出立体感"这一件事 |
| 多视角环绕观看 | 单屏视差方案没有侧后方视角，超出范围 |

> 语音、对话、人格记忆是独立的后续模块，可复用 `rehab-coach` 已有的 `sherpa-onnx` + `piper-tts` + `Qwen2.5-1.5B RKLLM`，不在本文档范围。

### 2.4 关键几何推论（**必须理解**）

1. **有效水平基线只有 47.23 mm，不是 61.64 mm**。深度计算必须用 `T_x`，用 `|T|` 会把距离高估约 30%。
2. **两目存在 39.5 mm 的轴向错位**（`T_z`），意味着左右视图的**尺度不同**（3m 处约差 1.3%）。这是原始拆半直接做模板匹配失败的根因。
3. **cx 相差 139.5 px 是真实的**，不是标定错误。实测原始拆半后存在稳定 `dx≈144 px` 的静态错位，与之一致。
4. 因此：**拆半 ≠ 可用立体像对，必须 `stereoRectify` + `remap` 之后才能算视差。**

### 2.5 三个待确认项（Step 1 需解决）

| # | 待确认 | 影响 | 处置 |
|---|---|---|---|

| 3 | `/dev/video22` 的作用 | 可能可拿到硬件时间戳 | 低优先，`v4l2-ctl --all` 查看 |

## 3. 为什么选路线 D

| 路线 | 内容 | 工作量 | RK3588 可行 | 恐怖谷风险 | 结论 |
|---|---|---|---|---|---|
| A | 实时双目点云"魂影" | 2 周 | 中（SGBM 吃 CPU） | 低 | 备选，作为演示模式保留 |
| B | 3DGS 数字人 + 骨骼驱动 | 1–2 月 | 渲染勉强（需 GPU 优化） | 中高 | 长期目标 |
| C | 多视角阵列 + 表情驱动 | 3 月+ | ❌ 需加硬件 | 高 | 不做 |
| **D** | **2.5D 分层视差（本文档）** | **9 天** | **✅ 轻松** | **最低** | **✅ 采用** |

**决策依据：**

1. **算力非对称**——重型计算（分割、深度）只在采集期跑一次，呈现期每帧只有追踪 + 顶点着色器，30fps 毫无压力。这与"一次采集、永久呈现"的怀念产品形态天然吻合。
2. **规避恐怖谷最彻底**——不做 3D 几何，只做"有厚度的影像"，大脑不会去挑建模瑕疵。
3. **失败成本低**——每一步都能出可见成果，不像重建路线要等一整套管线跑通才知道行不行。

## 5. 详细实现步骤

### Step 0 · 相机接管与分辨率确认（0.5 天）

**目标**：独占相机，确认实际输出与拆分正确。

**前置**：`rehab-coach` 的三个进程已停止（已完成，见附录 C）。

**做法**：

```python
import cv2
cap = cv2.VideoCapture('/dev/v4l/by-id/usb-CCB_Camera_CCB_Camera-video-index0')
cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc('M','J','P','G'))
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 2560)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 720)
cap.set(cv2.CAP_PROP_FPS, 30)

for _ in range(10):          # 丢弃前 10 帧，等 AE/AWB 收敛
    cap.read()
ok, frame = cap.read()       # 期望 (720, 2560, 3)
L, R = frame[:, :1280], frame[:, 1280:]
```

**踩过的坑**：

- 用索引 `cv2.VideoCapture(21)` 不抗设备重编号，**必须用 `/dev/v4l/by-id/` 稳定路径**。
- MJPG 必须显式设置，否则可能协商到不支持的模式。
- 前 10 帧有曝光/白平衡震荡，直接用于深度会产生跳变。

**验收**：`frame.shape == (720, 2560, 3)`，左右半帧画面内容连贯。

### Step 1 · 极线校正与深度真值（1.5 天）★ 最关键

**目标**：把原始拆分变成**可直接算视差的校正像对**，并得到稀疏但正确的双目深度真值。

> ⚠️ **这是本方案最容易出错的一步。** 原始拆半后的左右图存在约 144 px 静态错位和 1.3% 尺度差，**不校正直接跑 SGBM 会得到完全错误的结果**（实测出现"中位视差 44 px 但相关系数仅 0.01"的自相矛盾现象）。

**做法**：

```python
import cv2, numpy as np, json

calib = json.load(open('calibration/stereo_calib.json'))
M1, d1 = np.array(calib['camera_matrix_left']), np.array(calib['dist_coeffs_left'])
M2, d2 = np.array(calib['camera_matrix_right']), np.array(calib['dist_coeffs_right'])
R, T = np.array(calib['R']), np.array(calib['T'])
h, w = 720, 1280

R1, R2, P1, P2, Q, roi1, roi2 = cv2.stereoRectify(
    M1, d1, M2, d2, (w, h), R, T, alpha=0, flags=cv2.CALIB_ZERO_DISPARITY)

mapL = cv2.initUndistortRectifyMap(M1, d1, R1, P1, (w, h), cv2.CV_32FC1)
mapR = cv2.initUndistortRectifyMap(M2, d2, R2, P2, (w, h), cv2.CV_32FC1)

gL = cv2.remap(cv2.cvtColor(L, cv2.COLOR_BGR2GRAY), *mapL, cv2.INTER_LINEAR)
gR = cv2.remap(cv2.cvtColor(R, cv2.COLOR_BGR2GRAY), *mapR, cv2.INTER_LINEAR)
```

**SGBM 参数（建议初值）**：

```python
sgbm = cv2.StereoSGBM_create(
    minDisparity=0, numDisparities=128, blockSize=7,
    P1=8 * 3 * 7**2, P2=32 * 3 * 7**2,
    uniquenessRatio=10, speckleWindowSize=100, speckleRange=2,
    disp12MaxDiff=1, mode=cv2.STEREO_SGBM_MODE_HH)
disp = sgbm.compute(gL, gR).astype(np.float32) / 16.0
xyz  = cv2.reprojectImageTo3D(disp, Q)
```

**深度精度（用有效水平基线 47.23 mm 计算）**：

| 距离 Z | 视差 d = f·B/Z | 深度精度 δ Z = Z²·δd/(f·B)，δd=1/16 px |
|---|---|---|
| 1.0 m | 56.6 px | **1.1 mm** |
| 1.5 m | 37.7 px | 2.5 mm |
| 2.0 m | 28.3 px | **4.4 mm** |
| 3.0 m | 18.9 px | 9.9 mm |

> **结论**：1–2 m 肖像距离上深度精度 1–4 mm，**完全够用**。真正的短板不是精度，而是**皮肤/白墙等弱纹理区域的空洞率**——这正是 Step 3 引入单目深度的理由。

**验收标准**：

1. 极线校正后，同一棋盘格角点在左右图的 **y 差 < 1 px**；
2. 3 m 外参考物视差接近 0（验证 `CALIB_ZERO_DISPARITY` 生效）；
3. 1.2 m 处实测深度误差 < 2 cm；
4. SGBM 在人脸区域的有效像素率记录基线值（预期 30–60%）。

**若极线 y 差 > 2 px**：说明 `T` 或 `R` 有问题，用 20–30 张棋盘格重标定（28 mm 格距，9×6）。

### Step 2 · 单目深度模型上 NPU（1 天）

**目标**：得到稠密、边缘平滑、无空洞的相对深度图，用来补双目的空洞。

**模型选型**：

| 模型 | 输入 | int8 体积 | 说明 |
|---|---|---|---|
| **DepthAnything-V2-Small** | 518×518 | ~25 MB | **首选**，边缘质量最好 |
| MiDaS v2 small | 256×256 | ~10 MB | 备选，速度更快 |
| FastDepth | 224×224 | ~5 MB | 室内场景够用，边缘一般 |

**转换流程（必须在 x86 PC 上完成）**：

```bash
# PC 侧（x86 Linux，板子上只有 lite 运行时，不能转换）
pip install rknn-toolkit2
python convert.py                      # ONNX → RKNN int8
# 量化校准集直接用 rehab-coach/models/quant_images/ 里的现成图片
```

**板端推理**：

```python
from rknnlite.api import RKNNLite
rknn = RKNNLite()
rknn.load_rknn('depth_anything_v2_s.rknn')
rknn.init_runtime(core_mask=RKNNLite.NPU_CORE_AUTO)
out = rknn.inference(inputs=[resized_float])   # 返回相对深度（无量纲）
```

**性能目标**：518×518 单帧 **< 40 ms**。

**坑**：

- DepthAnything 输出是**相对视差**（大 = 近），不是深度，也不是米。**直接当深度用会得到错误结果**，必须过 Step 3。
- int8 量化对深度模型的远端精度损伤明显，量化后要与 fp32 输出做一次逐像素对比，`abs diff` 的 p95 应 < 满量程的 5%。

### Step 3 · 把相对深度变成米（0.5 天）★ 不可跳过

**目标**：把无量纲的相对深度映射为米制深度，使视差幅度物理正确。

**方法：用双目做标尺，最小二乘拟合**

```python
# 同一帧上：depth_stereo 稀疏但正确，rel 稠密但无尺度
z_stereo = xyz[:, :, 2]
mask = (z_stereo > 0.3) & (z_stereo < 5.0) & np.isfinite(z_stereo)

inv_z = 1.0 / z_stereo[mask]                    # 1/Z 与视差成正比，几何上更合理
A = np.stack([rel[mask], np.ones(mask.sum())], 1)
a, b = np.linalg.lstsq(A, inv_z, rcond=None)[0]

depth_metric = 1.0 / np.clip(a * rel + b, 1e-3, None)
```

**更稳的交叉验证（推荐同时做）**：利用人脸先验——瞳距 ≈ 63 mm、脸宽 ≈ 140 mm。检测 106 点取瞳心，双目三角化出距离，反解尺度。人像场景下这个先验比稀疏 SGBM 更鲁棒。

**验收标准**：屏幕上量出的深度范围（如 0.9–1.8 m）与卷尺实测相差 **< 10%**。

**坑**：`a` 的符号要检查——DepthAnything 输出"越大越近"，所以 `a` 应为正。若拟合出的 `a` 近 0 或为负，说明 SGBM 真值有误，回到 Step 1。

### Step 4 · DIBR 网格位移渲染（2 天）★ 核心

**目标**：视点移动时，画面按深度分层产生正确的反向位移。

**不要做硬分层。** 把深度切成 8–12 层会出现层间割裂感。正确做法是**网格变形**：

把 (RGB, depth) 建成一张 `160×90` 顶点网格，每顶点 `z` 取该点深度。

**渲染数学（重要：不要直接套用采集焦距）**

直觉上应该用 `parallax = f·t_x/Z`，但代入采集内参会得到灾难性结果：`f=1198, t_x=0.15m, Z=0.9m → 200 px` 位移，画面会崩。

正确做法是把深度**重映射到一个虚拟显示空间**，再按显示参数计算位移：

```glsl
// vertex shader 核心
attribute float aDepthNorm;   // 0.0=最近, 1.0=最远
uniform vec3  uEye;           // 眼点偏移，归一化到 [-0.5, 0.5]
uniform float uFocus;         // 焦点深度（人物主体所在层）
uniform float uGain;          // 视差增益，单位 px

void main() {
    // 1) 映射到虚拟显示深度：焦点处位移为 0
    float z = mix(0.45, 1.75, aDepthNorm);       // 虚拟深度 0.45~1.75 m（设定值）
    float parallax = uGain * (1.0/uFocus - 1.0/z) * 2.0;

    // 2) 前层反向、后层同向，形成相对位移
    vec3 p = aPos;
    p.xy += uEye.xy * parallax;
    gl_Position = uProjection * uModelView * vec4(p, 1.0);
}
```

**参数建议初值**：`uGain = 80 px`（对应眼动 ±0.15 m，画面位移约 ±12 px，肉眼清晰可辨且不晕）。`uFocus` 取人脸所在深度。

**空洞处理（决定成败）——前层遮挡法**

网格拉伸后人物边缘会拉出空洞。分两遍画：

1. **背景层**：同一张图放大 2% + 高斯模糊（σ≈8），先画满屏
2. **人物层**：用 `matte.png` 做 alpha，后画

视觉上自然呈现为"主体实、背景虚"，拉丝被背景层填掉。

**实现选型**：直接用 **Qt `QOpenGLWidget`**，复用 `rehab-coach/src/qt_gui/` 的编译脚本（`scripts/build_linux.sh`，产物 `prograss_copy`），改造成本最低。

**验收标准**：

1. 头左右移动 ±15 cm，人物与背景产生**方向相反**的位移，幅度 ≥ 8 px；
2. 头发/肩线边缘无 ≥ 3 mm 的拉丝或破洞；
3. 呈现帧率 ≥ 30 fps。

**坑**：

- 纹理配准必须按 `depth` 而不是 `matte` 做，否则边缘错位。
- 网格分辨率不要过高（>320×180）否则顶点着色器成瓶颈；也不要过低否则出现折面。160×90 是实测甜点。
- GLSL 在板子上调试痛苦，**先在 PC 上用 OpenGL 调通再搬**。

### Step 5 · 观众眼位追踪（2 天）

**目标**：实时、低延迟地拿到观众头部/眼睛在相机坐标系中的 3D 位置。

**做法**：

1. **人脸关键点**：`yolov8n-pose.rknn` 是人体姿态模型，不适合脸部细节。建议换成 106 点 face landmark（PIPNet / 2d106det 轻量版，同样可转 RKNN）；先跑通可用 OpenCV `FacemarkLBF`。
2. **取哪一点**：优先虹膜中心。简化版取**鼻尖 + 两瞳中点**，误差可接受。
3. **转 3D**：用双目 SGBM 深度在鼻尖邻域取中值，得 `(x, y, z)` 米。
4. **平滑**：**One-Euro Filter**（低延迟场景显著优于卡尔曼）：

```python
# 建议参数：mincutoff=1.5 Hz, beta=0.01, dcutoff=1.0
alpha = 1.0 / (1.0 + (2*math.pi*cutoff*dt))
x_filtered = alpha*x_prev + (1-alpha)*x
```

**必须做的一步：camera ↔ screen 外参标定**

漏掉这步，视差会"不跟手"且方向错误。

```
屏幕上显示已知尺寸的棋盘格 → 用相机拍下来
→ cv2.solvePnP(棋盘格角点3D, 图像点2D, 相机内参, 畸变)
→ 得到屏幕平面在相机坐标系中的位姿
→ 建立「屏幕像素坐标 ↔ 相机 3D 坐标」双向映射
```

**延迟预算**：

| 环节 | 耗时 |
|---|---|
| 采集（30fps） | 33 ms |
| 人脸检测 + 关键点 (NPU) | 15 ms |
| 平滑 | 10 ms |
| 渲染 | 16 ms |
| **合计** | **≈ 75 ms** |

> **硬指标：端到端 < 100 ms。** 超过会产生眩晕感，不可接受。

**验收标准**：头部快速左右移动，画面视差跟随流畅、无抖动、无可见滞后。

### Step 6 · 微动：制造"活着"的感觉（1 天）★ 情感核心

**目标**：让静止影像具有生命体征。

> 这一步对最终效果的影响，**远大于渲染精度**。人脑对"活着"的判定主要来自微动，而不是分辨率。

| 微动 | 实现方式 | 参数 |
|---|---|---|
| 呼吸 | 整体纵向正弦缩放 | ±0.3%，周期 3.5–5 s，带 15% 随机抖动 |
| 眨眼 | 3–5 帧眼部开合图交叉淡化 | 3–7 s 随机触发，过渡 80 ms |
| 微摆 | 头部区域（按深度选上层）低频摆动 | ±0.5°，叠加极轻微水平漂移 |
| 亮度呼吸 | 画面整体亮度极缓起伏 | ±0.2% |

**核心原则**：所有幅度都要小到**"说不清哪里在动"**。一旦观众能明确指出"它在动"，恐怖感立刻产生。

**加分项（可选，效果显著）**：呼吸节奏可以从**真实视频**中提取，而不是程序化正弦——用相位相关做亚像素级帧间位移估计，胸廓起伏可达亚毫米精度。这比正弦波有说服力得多，值得做。

|---|---|---|

| 颗粒 | 极淡 film grain | 掩盖深度边缘的锯齿 |
| 背景 | 最远层景深虚化 + 反向视差 | 强化纵深 |

### Step 8 · 呈现形态升级（可选，1 天）

| 方案 | 效果 | 成本 |
|---|---|---|
| 普通显示屏 | "窗口感"：能看出纵深，但人物出不了屏 | 0 |

- 环境光要暗，背景必须是纯黑

## 6. 性能预算

### 6.1 采集期（一次性，不要求实时）

| 环节 | 耗时 | 硬件 |
|---|---|---|
| 采集 + MJPG 解码 | 25 ms | A76 |
| 极线校正 remap | 12 ms | A76 |
| SGBM（1280×720） | **510 ms** | A76 ×8（实测，见 §12.4） |
| 单目深度（518×518） | 35 ms | NPU |
| 人像分割 | 15 ms | NPU |
| **合计** | **≈ 600 ms/帧**（实测） | — |

> 采集 60 秒约 1800 帧；按 600 ms/帧算需 18 分钟——**因此 SGBM 只用于标定抽样**，
> 不做逐帧处理。若将来需要稠密视频深度，降到半分辨率可换 8 倍速度（见 §12.4）。

### 6.2 呈现期（持续 60 fps）

| 环节 | 耗时 | 硬件 |
|---|---|---|
| 采集（30fps） | 33 ms | A76 |
| 人脸检测 + 关键点 | 15 ms | NPU |
| 平滑 | 10 ms | A76 |
| DIBR 渲染 | 16 ms | Mali-G610 |
| **合计** | **≈ 75 ms** | — |

### 6.3 优化手段（若达不到 30 fps）

1. **采集降到 30 → 20 fps**，渲染插值，观感几乎无损
2. **人脸检测降频**：每 2–3 帧跑一次，中间用光流/位移预测插值
3. **渲染只更新变化区域**：眼位变化小于 1 px 时跳过重绘
4. **CPU 亲和性**：A76 前 4 核专给视觉，A55 给音频/IO/网络
5. **不要同时加载 LLM**（Qwen2.5-1.5B 占 2 GB 内存），演示模式下按需加载

## 11. 隐私与伦理红线（不可妥协）

> 这是"怀念"类产品，做错了会真实伤害人。

1. **全部本地化**：影像、深度、声音不出设备，不联网，不上云。
2. **静态加密**：`assets/` 目录整体加密存储，密钥不落盘明文。
3. **明确标注"这是模拟"**：界面上必须有可见标识，并提供防伪开关。此类技术最大的滥用方向是"复活式诈骗"。
4. **不做 24 小时陪伴**：持续使用会加重**延长哀伤障碍（Prolonged Grief Disorder）**。必须设计：
   - 「纪念日模式」与「日常模式」分离
   - 单次使用时长提示
   - 有仪式感的"关闭/告别"过渡动画
5. **知情同意**：被采集者生前须明确同意其影像被用于此用途，且可随时撤回。
6. **设计文档第一行**：**目标不是让他回来，是让你能好好说再见。**

## 12. 实测修正记录（Step 0–1 回填）

> 本节记录实施过程中被实测推翻的假设。**与前面章节冲突时以本节为准。**

### 12.1 相机帧率：`BUFFERSIZE=1` 会把帧率砍半

实测（2560×720，同一场景连续采 40–50 帧）：

| BUFFERSIZE | 实测 fps | 中位间隔 |
|---|---|---|
| 1 | **14.8** | 67.7 ms |
| 2 | **31.1** | 32.2 ms |
| 4（驱动默认） | 31.1 | 32.2 ms |

仅 `grab()` 不解码时同样是 14.8 fps，证明**不是解码瓶颈，是驱动没有空闲 buffer 可填**。
结论取 `BUFFERSIZE=2`（满帧且排队帧数最少）。已写入 `capture/camera_io.py`。

### 12.2 标定文件不可用（推翻 §2.3–§2.5）

### 12.7 深度尺度标定（两点法）与深度模型修正

**深度不能用教科书公式 `Z = f·B/d`。** 本机两目主点不一致，存在一个很大的
固有视差偏移 `d_inf ≈ -156 px`——它的绝对值比物体视差本身还大，漏掉会让深度差出数倍。

正确模型：

```
Z = K / (d - d_inf),   K = fx · B
```

**标定过程**：用户把雪糕筒放在两个位置并报告距离，用颜色分割取出目标红色反光条，
读其中位视差（两帧间极稳，p25/p75 差 < 1 px）：

| 位置 | 用户标注 | 实测中位视差 |
|---|---|---|
| A | 1.2 m | **-109.84 px** |
| B | 2.4 m | **-133.03 px** |

背景视差两次测量分别为 -143.69 / -143.56 px，说明**相机未被移动**，两点可比。

**解算**：两点距离比实测精确为 2.000，但绝对距离约为标注值的 1.12 倍
（推测为迈步估算）。代入 nominal 基线 52.0 mm 反推，实际位置为 1.344 / 2.688 m，
三者完全自洽。

> `d_inf` 只依赖两点的**距离比**，与绝对尺度无关，因此即使绝对距离有偏差也稳健。

**标定结果**（`config/depth_calib.json`）：

| 参数 | 值 |
|---|---|
| fx | 1198.7 px |
| B | 52.0 mm（nominal；\|T\|=61.64mm 来自同一份已证伪的标定，不采用） |
| K = fx·B | 62.3324 px·m |
| d_inf | **-156.22 px** |

**验证**：路障实测深度 **2.710 m**，推算值 2.688 m，误差 **+0.8%**（2 cm）。

**1–2 m 肖像距离的深度分辨率**（视差量化 1/16 px）：

| Z | 分辨率 |
|---|---|
| 1.0 m | 1.00 mm |
| 1.2 m | **1.44 mm** |
| 1.5 m | 2.26 mm |
| 2.0 m | 4.01 mm |

> 结论：肖像距离上双目深度精度达毫米级，**远超 2.5D 视差渲染所需**
> （渲染只需要厘米级的分层）。

### 12.9 Step 2 实测：单目深度上 NPU

**模型**：DepthAnything-V2-Small，输入 518×518（=37×14），静态化后转 RKNN。

转换链路（工具链见 `docs/toolchain.md`）：

```
HF ONNX（动态 shape [B,3,H,W]，823 节点）
  ↓ 手写固定 input/output 维度

  ↓ onnxsim 折叠 Shape/Gather/Reshape 等动态算子
simplified ONNX
  ↓ rknn-toolkit2 2.3.2，ImageNet 归一化烘焙进模型

```

> **归一化必须烘焙**：`rknn.config(mean_values/std_values)` 作用在 0–255 输入上，
> 取 ImageNet 统计量 ×255（mean≈[123.7,116.3,103.5]，std≈[58.4,57.1,57.4]）。

| 版本 | 体积 | 单次推理 | 精度 |
|---|---|---|---|
| **fp16（采用）** | 57.5 MB | **763 ms**（1.3 fps） | 基准 |

这说明该模型在 RK3588 上的瓶颈不是算力，而是算子调度与内存开销

| 资产 | rgb.png 1.2 MB + depth.f32 3.5 MB |

远高于 30 fps 目标，渲染不是瓶颈。

### 12.13 焦点参数的语义修正（重要设计结论）

做肖像演示时踩了一个概念错误：**把 `z_focus` 设成主体深度，结果主体完全不动。**

因为 `z_focus` 是**零视差面**（等价于"屏幕那块玻璃"）：

```
parallax ∝ (1/z_focus − 1/z)
```

- `z_focus` 放在主体上 → 主体位移恒为 0，看起来是"贴在屏幕上"的死图
- `z_focus` 放在背景上 → 背景不动，主体浮出来 —— **这才是想要的效果**

因此资产里三个深度参数的正确含义是：

| 参数 | 含义 | 典型取值 |
|---|---|---|
| `z_focus` | 零视差面（屏幕平面） | 背景深度，如 4.2 m |
| `z_split` | 前景层阈值：比它近的才走全视差 | 主体深度 ×1.8，如 2.6 m |
| `z_subject` | 主体深度（仅供参考/HUD） | 1.45 m |

`z_split` 必须显式给出并大于主体深度，否则主体会落进背景层、完全没有视差。
原代码用 `z_focus × 0.6` 推导，在肖像场景下是错的。

### 12.14 背景虚化消除 DIBR 鬼影

DIBR 的固有问题：主体移开后，原位置露出的是"背景层里的原主体"——
因为我们没有主体身后的真实背景，形成**鬼影/重影**。

低成本缓解：背景层改用**预模糊贴图**（缩到 1/10 再放大）。

- 鬼影变成一个柔和团块，不再有清晰的人物轮廓
- 同时得到"主体清晰、背景虚化"的景深效果，正好符合怀念影像的美术方向
- 代价：一次 CPU 缩放，零运行时开销

彻底解决需要主体分割 + 背景修补（inpaint），留作后续优化。


### 12.15 Step 5 实做：眼位追踪

**复用 rehab-coach 的 YOLOv8n-Pose RKNN**，输出 17 关键点，取 `nose`
（退化时取双眼中点）作为头部位置。

> ⚠️ 必须用 **fp16** 版 `yolov8n-pose.rknn`。int8 全量化版置信度全为 0，
> rehab-coach 自己也有这条警告，实测确实检不出人。

**为什么不做真正的 3D 反投影**

单目没有绝对深度；用瞳距（63 mm）反推 Z 会引入更多噪声。而 DIBR 需要的
只是一个**归一化相对视点**——因为视差量本身已经含了 `1/z`，eye 与观看距离无关：

    eye_x = (nose_x - cx) / (sens · half_w)

`sens` 是灵敏度（1.0 = 头移到画面边缘即满偏）。输入侧做指数平滑（α=0.35）抑制关键点抖动。

**通信**：UDP `127.0.0.1:9999`，一行 ASCII `ex,ey\n`；检测不到人发 `nan,nan`，
渲染端保持上一次位置并在 1.5 s 后自动退回鼠标/自动摆动模式。

用 UDP 而不是共享内存/管道的原因：追踪器和渲染器是两个独立进程，
UDP 无连接、丢一帧无所谓、且渲染器可以独立启动（没有追踪器时仍能用鼠标演示）。

**实测**：

| 环节 | 结果 |
|---|---|
| 离线单图检测（1272×712 肖像） | 52.4 ms，人体置信度 0.856，鼻尖 (564,378) |
| 实时（相机 2560×720 取左目） | **12 fps** |
| UDP → 渲染器 | ✅ 注入 `0.80,0.20` 后 HUD 显示"眼动追踪"，视差按值生效 |
| 渲染帧率 | 33 fps（与追踪器并行运行） |

12 fps 对眼位追踪够用（配合平滑滤波），瓶颈在 pose 推理本身。

### 12.16 背景板：彻底消除 DIBR 鬼影

§12.14 的模糊背景只能*弱化*鬼影。接入眼动追踪后视差变大，重影又变得明显。

**根治办法**：用深度把主体抠掉，修补出一张干净背景板。

```
mask = depth < z_split          # 主体区域（本例 17.1% 画面）
mask = dilate(mask, 9) × 2
bg   = inpaint(rgb, mask)       # tools/make_bg.py
```

渲染时背景层用 `bg.png`，主体移动后露出的就是**真正的背景**，不再是自己。
没有 `bg.png` 的资产自动退回模糊原图。

效果对比：注入 `eye=(0.80,0.20)` 的大视差下，接背景板前人物有清晰重影，
接背景板后只剩轻微边缘光晕。`tools/make_asset.py` 已自动生成 `bg.png`。


### 12.17 人像抠图（MODNet）：替代深度阈值遮罩

**问题**：V1 用 `depth < z_split` 当遮罩，没有语义。头发、肩膀这些深度和背景
接近的地方必然糊，且没有 alpha 羽化，导致背景板 inpaint 边界脏、前景合成有光晕。

**方案**：MODNet（专为人像/视频抠图设计，发丝级边缘）。

转换链路与深度模型一致：

```
Xenova/modnet ONNX（25 MB, 487 节点, 动态 shape）
  ↓ 固定 [1,3,512,512] -> [1,1,512,512]
  ↓ onnxsim（487 -> 234 节点）
  ↓ mean=std=127.5（MODNet 的 (x/255-0.5)/0.5 归一化烘焙）
modnet.rknn（22 MB）
```

**实测（RK3588）**：

| 指标 | 值 |
|---|---|
| 推理耗时 | **286 ms / 帧**（512×512） |
| 输出范围 | 0.002 ~ 0.998（连续 alpha，正常） |
| 主体覆盖 | 15.4% |
| 软边（羽化）像素 | 1.26% |

286 ms 看着慢，但 **matte 每个资产只算一次**（离线），不影响产品帧率。
对比深度模型 763 ms/帧——两者都是一次性成本。

**接入效果**：

1. 渲染器新增 `matte.png` 纹理，前景层 alpha 直接用它
   （没有 matte 的资产自动退回深度阈值）
2. `make_bg.py` 用 matte 做 inpaint 掩码，背景板边界比深度掩码干净得多
3. 结果：**大视差下完全无鬼影**，边缘自然

**顺带解锁的能力**（后续可用）：换背景、半透明魂影、主体描边辉光——
这些全都需要 alpha，之前做不了。


### 12.18 美术风格化：三档风格与"魂影"模式

有了 matte 之后，才第一次能做真正的前景合成。实现三档风格（`S` 键循环）：

| 风格 | ghostAlpha | 辉光 | 调色 | 适用 |
|---|---|---|---|---|
| **清晰** | 1.00 | 0.30 | 0.25 | 近距离端详 |
| **回忆** | 1.00 | 0.55 | 0.75 | 日常 |
| **魂影** | **0.78** | 0.95 | 1.00 | **规避恐怖谷** |

**渲染管线**（三个 pass）：

```
pass 0  背景：bg.png（模糊），grade + 暗角，不位移
pass 1  前景：rgb × matte × ghostAlpha，全增益视差
pass 2  辉光：rim = pow(blur(matte) - matte, 0.6) × glow，叠加混合(GL_ONE, GL_ONE)
```

辉光贴图是 matte 的模糊版（预生成），着色器里 `blur(matte) - matte` 正好得到
轮廓外侧的一条带——不需要额外采样，零运行时开销。

**调色函数**（`grade()`）：

- 降饱和 18%（乘 uGrade）
- 偏暖：`(1.07, 1.00, 0.93)`
- 提黑位：`c * 0.93 + 0.035`（褪色胶片感）

**踩的坑**：第一版辉光几乎看不见，因为 `blur(matte) - matte` 的差值本身很小（约 0.3）。
加了 `pow(rim, 0.6)` 提亮并乘 2.2 之后才真正可见。

**为什么这一档重要**：恐怖谷的本质是"太像但又不完全像"。半透明主体 + 轮廓辉光
明确告诉大脑"这不是真人"——反而让观看者放松，注意力回到情感本身。
这是怀念类产品最稳妥的视觉语言。


### 12.19 Step 7 实做：采集向导 + 实时质检

在向导之前，采集靠人肉判断"站得对不对"，标定脚本和资产生成又是两套独立流程。
这一节把它们合并成一条可引导的流水线。

**分层设计**：先把「采集→标定→出资产」抽成公共模块 `capture/pipeline.py`，
`tools/mono_calib.py` 与 `tools/capture_wizard.py` 共用，避免两份逻辑漂移。

| 函数 | 职责 |
|---|---|
| `process_frame` | 校正 + 裁切 + 双目深度 + 单目相对深度 |
| `fit_affine` | 鲁棒拟合 `1/Z = a·rel + b` |
| `evaluate` | 棋盘留出集 + 分深度段误差 |
| `write_asset` | 写 rgb/depth/matte/meta（含 z_focus / z_split / z_subject） |
| `write_background` | 用 matte 做 inpaint 掩码生成 bg.png |

**质检项**（实时，基于 YOLOv8-pose 的框与鼻尖）：

| 检查 | 判据 | 级别 |
|---|---|---|
| 检测到人 | pose 返回 bbox | **硬性** |
| 亮度 | 主体区域平均灰度 > 48 | **硬性** |
| 距离 | 人体框高度占画面 0.42–0.97 | 建议 |
| 居中 | 鼻尖水平偏移 < 0.20 | 建议 |
| 逆光 | 主体/背景亮度比 > 0.42 | 建议 |
| 清晰度 | 主体区域拉普拉斯方差 > 55 | 建议 |

**为什么分硬性/建议**：门限全设成硬性会导致永远拍不了（比如逆光环境下清晰度
天然偏低）。只把"有人"和"亮度够"设为硬门槛，其余提示但不阻止——
这是可用性的关键取舍。

**交互**：`SPACE` 立即采集、`A` 自动（通过后倒计时 3 秒）、`Q` 退出。
中文叠加层用 Pillow 渲染（`cv2.putText` 不支持中文，`cv2.freetype` 在
本机 opencv 构建里不可用）。

**踩的坑**：

- `cv2.namedWindow` 默认带工具栏（缩放/保存按钮），占掉画面上方一行，
  要加 `cv2.WINDOW_GUI_NORMAL` 才干净
- 叠加层用 `✗`/`✓` 会显示成方块（Noto CJK 无该字形），改用「必须：/建议：」纯中文标记

**验证**：UI 与预览正常；后处理链路已用办公室场景实跑验证——
2 帧 → 标定 → rgb/depth/matte/bg/meta 五个文件全部正确生成。

### 12.20 程序化眨眼

没有真实眨眼素材时，用图像变形合成一张"闭眼"图，渲染时与睁眼帧交叉淡化。

**合成方法**（`capture/blink.py`）：

```
对每只眼睛：
  1. 按瞳距自适应眼眶尺寸（半宽 0.26×瞳距，半高 0.17×瞳距）
  2. 取眼睛上方一条皮肤带（上眼睑）
  3. 纵向拉伸覆盖整个眼眶
  4. 羽化后贴回
```

这模拟"上眼睑下垂盖住眼球"，在 160 ms 的眨眼时长下足够可信。

**踩的坑**：第一版把眼眶半宽设成 **0.78×瞳距**，矩形大到把整张脸盖住，
预览里是一个大黑块。人体测量给出的正确值是眼宽 ≈ 0.48×瞳距（半宽 0.24）。
改到 0.26 之后差异图精确落在两只眼睛上（改动像素仅 0.20%）。

**渲染接入**：

| 项 | 实现 |
|---|---|
| 素材 | 资产里多一张 `blink.png` |
| 混合 | 片段着色器 `mix(睁眼, 闭眼, uBlink)` |
| 节奏 | 随机间隔 2.5–6 s，单次 160 ms（闭 64 / 停 32 / 睁 64） |
| 无素材时 | 自动跳过，不影响渲染 |

算法与素材解耦：将来有真实眨眼视频帧，只要替换 `blink.png` 即可，
渲染端不用改。


### 12.21 眼神回望：头部局部反向位移

**要解决的问题**：DIBR 的视差是全局的——观众右移，头会像"窗外的物体"一样向左滑。
但真人转头看你是反过来的：你往右移，他的头朝右转。这两件事方向相反，
不区分就会一直显得"没在看你"。

**做法**：给头部区域加一个与视差**反向**的额外位移。

```
pos = aPos + 视差位移 + eye × gaze × gazeGain × headMask
```

- `headMask`：姿态关键点推出的头部椭圆（半宽 1.40×瞳距，半高 1.80×瞳距），
  羽化后与人像 matte 相交
- `gaze`：0..1，追踪到人时在 ~0.5 s 内平滑升到 1，丢失时降回 0
- `gazeGain`：20 px

净效果：头部比身体少位移 10 px 左右，读起来就是"头转过来看你"。

**为什么不用真正的 3D 头部旋转**：2.5D 平面图像没有头部背面信息，
真旋转会露出空洞。小幅横向位移是这类"平面重投影"最稳的表达。

**踩的两个坑**：

| 问题 | 原因 |
|---|---|
| 回望完全不生效 | 快照模式里 Viewer 定时器按"未追踪"把 gaze 衰减到 0，覆盖了 `--gaze`。加 `--gaze` 锁定 |
| 头部遮罩盖错人 | 画面里有同事，`pick_person_index` 选中了最右边的远景人物（瞳距 14.7 px）。改为只在**画面中央 62% 区域**检测再映射回原坐标 |

**实测**：`--gaze 0` vs `1` 差异像素 3.6%，差异图完全集中在头部；
身体与背景不受影响。
